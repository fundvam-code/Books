# Сборка и печать заказов Ozon

Добавить на карточки новых FBS-заказов Ozon две кнопки: «Отправить в сборку» переводит заказ в `awaiting_deliver`; «Собрать и напечатать» выполняет тот же переход, запрашивает этикетку и отправляет PDF в существующую очередь печати локального агента. Статус «Напечатано» ставится только после ответа принтера `submitted`.

В карточках заказов убрать дату отгрузки, показать миниатюру обложки книги и увеличивать её при наведении. Дату создания карточки товара показывать в подробностях заказа. Обложку и дату брать из локальной синхронизации Ozon Product Info и WB Content API; браузер не должен обращаться к маркетплейсам напрямую.

Ozon API вызывается только локальным агентом с ключами кабинета. Для сборки применяется `POST /v4/posting/fbs/ship`, `product_id` берётся из `sku`; агент подтверждает фактический `awaiting_deliver` через получение отправления. Печать использует существующие задания этикетки и очередь, без браузерной печати. Если агент или принтер недоступен, дашборд показывает состояние/ошибку, а отметка печати не ставится.

Для изображений и даты Ozon нужен доступ Product на чтение; отсутствие права не должно мешать загрузке заказов. WB продолжает получать эти поля из уже используемого Content API.

Защита от повторного нажатия и повторов API обязательна: одно активное задание на кабинет и отправление, а сборка уже переведённого или отменённого заказа не запускается. Вызов работает только при доступном агенте, объявившем ключ Ozon для записи. Не вызывать Ozon API для проверки в рамках разработки.

Рассмотрены варианты: выполнить Ozon-запрос на сервере (нарушает выбранную схему и российский IP агента), связать интерфейс напрямую с API (раскрывает ключ) или провести обе операции через очередь локального агента (выбранный вариант; сохраняет секреты локально и повторно использует печать).
