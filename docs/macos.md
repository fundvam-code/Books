# Запуск дашборда на macOS

На Mac работают дашборд, PostgreSQL, Caddy и агент печати. Интерфейс открывается на этом Mac по адресу `https://127.0.0.1:8443/orders`. Mac должен быть включён, пользователь должен войти в macOS, а сеть должна давать доступ к API Ozon и Wildberries. Внешний домен и публичный сервер после переключения больше не нужны.

Рабочая база остаётся на сервере до согласованного окончания работы. Все предварительные шаги ниже можно выполнить с пустой базой и выключенным агентом.

## Подготовка Mac

1. Установите и запустите [Docker Desktop для вашего Mac](https://docs.docker.com/desktop/setup/install/mac-install/) с Compose 2.30 или новее. Включите запуск Docker Desktop при входе в систему. Установите Python 3.12 или новее и добавьте принтер через настройки macOS.
2. Клонируйте репозиторий в каталог, доступный текущему пользователю, и подготовьте файлы настроек.

   ```bash
   git clone https://github.com/fundvam-code/Books.git marketplace-dashboard
   cd marketplace-dashboard
   umask 077
   cp .env.macos.example .env.macos
   cp .env.agent.example .env.agent
   python3 -m venv .venv
   .venv/bin/python -m pip install 'httpx>=0.28,<1'
   lpstat -p -d
   ```

3. Оставьте `PUBLIC_DOMAIN=127.0.0.1` в `.env.macos`. Задайте имя пользователя и два независимых секрета для `POSTGRES_PASSWORD` и `AGENT_SHARED_SECRET`. Для каждого можно выполнить `openssl rand -hex 32`. Хеш пароля браузера получите командой `docker run --rm -it caddy:2-alpine caddy hash-password`. Запишите его в одинарных кавычках в `DASHBOARD_PASSWORD_HASH`. Если текущий дашборд использует Google Sheets для мест хранения, перенесите `BOOK_STORAGE_SHEET_ID` и `BOOK_STORAGE_SHEET_GID`.
4. В `.env.agent` задайте `DASHBOARD_URL=https://127.0.0.1:8443`, тот же `AGENT_SHARED_SECRET`, `DASHBOARD_CA_FILE=data/macos-caddy-root.crt` и имя очереди в `OZON_PRINTER`. Значение `default` использует принтер macOS по умолчанию. Перенесите файлы ключей площадок по защищённому каналу, следуя [настройке кабинетов](deploy.md#пк-с-агентом). Если файл Ozon теперь лежит в корне клона, укажите `OZON_ENV_FILE=.env.ozon`. Ключи, экспорт базы и этикетки храните вне Git.
5. Сравните ревизию приложения на сервере и в клоне Mac. Узнайте фактически развёрнутую ревизию у того, кто запускал сервер, если образ был собран из рабочей копии. В релиз для Mac должны входить все функции и изменения схемы, уже работающие на сервере. Если на сервере есть неопубликованный код, сначала включите его в согласованную ревизию и пересоберите образ Mac.

## Проверка без рабочей базы

Выполняйте команды из корня проекта. Для репетиции используется отдельный проект Compose со своими томами. Если порт занят, поменяйте его в `.env.macos`, `.env.agent` и командах проверки.

```bash
mac() { docker compose --env-file .env.macos -f compose.server.yaml -f compose.macos.yaml "$@"; }
export COMPOSE_PROJECT_NAME=books-rehearsal
mac config --quiet
mac up -d --build --wait
mkdir -p data
mac exec -T caddy cat /data/caddy/pki/authorities/local/root.crt > data/rehearsal-root.crt
curl --fail --cacert data/rehearsal-root.crt --user ИМЯ https://127.0.0.1:8443/health
```

`curl` запросит пароль браузера и должен вернуть `{"status":"ok"}`. Для проверки интерфейса в Safari или Chrome добавьте `data/rehearsal-root.crt` в связку ключей входа и задайте доверие для SSL. CA относится только к проекту репетиции. Проект, созданный для рабочего запуска, выпустит свой CA. При необходимости ограничьте репетицию проверкой через `curl`.

Когда проверка пройдёт, освободите локальный порт.

```bash
mac stop
unset COMPOSE_PROJECT_NAME
```

Пустой проект можно использовать и для нового развёртывания без истории. Тогда вместо восстановления выполните команды из раздела «Первый рабочий запуск» с выбранным постоянным именем проекта.

## Перенос после окончания работы с базой

Согласуйте короткую паузу для финальной копии. Во время неё приложение не принимает изменения. Сохраните текущую настройку автоматического мониторинга, если он есть. Выключите мониторинг, прекратите создавать новые задачи и дождитесь завершения активной сборки и печати. Сверьте сомнительные результаты с кабинетами и очередью CUPS. Штатно остановите текущий агент его обычным способом. Запишите его адрес и способ запуска для отката.

1. В каталоге действующего проекта на сервере остановите только веб-приложение. PostgreSQL должен остаться запущенным. Скопируйте `scripts/dashboard-data` из этого репозитория на сервер, например в домашний каталог. Для копии используйте ещё не существующий каталог. Сохраняйте имя проекта Compose и исходные параметры запуска сервера.

   ```bash
   docker compose --env-file .env.server -f compose.server.yaml stop dashboard
   bash "$HOME/dashboard-data" backup server "$HOME/books-final"
   ```

   Перенесите каталог `books-final` целиком на Mac, например через SCP. В нём должны быть `dashboard.dump`, `labels.tar.gz` и маркер `complete`. Если копирование сорвалось, для повторной выгрузки задайте новое имя каталога. Для отмены переключения до начала записи на Mac верните старый сервис по инструкции отката ниже.

2. На Mac задайте постоянное имя отдельного проекта. Запустите только базу, соберите образ и загрузите копию. Для восстановления нужны свежие тома. Скрипт откажется писать при запущенном дашборде или занятых целевых томах.

   ```bash
   export COMPOSE_PROJECT_NAME=books-local
   mac() { docker compose --env-file .env.macos -f compose.server.yaml -f compose.macos.yaml "$@"; }
   mac build dashboard
   mac up -d --wait database
   scripts/dashboard-data restore macos "$HOME/books-final"
   ```

   Если восстановление прервалось после распаковки PDF, используйте новое имя проекта для следующей попытки. Сохраните итоговое имя в `.env.macos` как `COMPOSE_PROJECT_NAME=books-local` или каждый раз экспортируйте его перед обращением к Compose.

## Первый рабочий запуск

```bash
mac up -d --wait
mkdir -p data
mac exec -T caddy cat /data/caddy/pki/authorities/local/root.crt > data/macos-caddy-root.crt
curl --fail --cacert data/macos-caddy-root.crt --user ИМЯ https://127.0.0.1:8443/health
```

Добавьте рабочий CA `data/macos-caddy-root.crt` в связку ключей входа с доверием для SSL. Откройте `https://127.0.0.1:8443/orders` и войдите. До запуска агента сравните историю печати, отметки заказов, справочник мест хранения и имеющиеся PDF с серверным снимком. PDF доступны в пределах срока хранения приложения. Мониторинг может сохранять состояние в базе, поэтому проверяйте его статус до подключения агента.

Убедитесь, что агент старой системы остановлен и что локальный интерфейс открывается без предупреждений о сертификате. Для первой проверки запустите `.venv/bin/python -m agent.run_macos` в терминале. Проверьте статус агента, обновление всех подключённых кабинетов, наличие своих PDF и тестовую печать согласованной этикетки. Восстановите нужную настройку мониторинга после сверки очереди.

Для постоянной работы остановите тестовый процесс через Ctrl+C, затем зарегистрируйте [пользовательский LaunchAgent](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html).

```bash
agent_plist="$(.venv/bin/python scripts/install-macos-agent.py)"
plutil -lint "$agent_plist"
launchctl bootstrap "gui/$(id -u)" "$agent_plist"
launchctl print "gui/$(id -u)/com.fundvam.books.agent"
```

Журнал агента находится в `data/macos-agent.log`. Для применения изменений в ключах используйте `launchctl kickstart -k "gui/$(id -u)/com.fundvam.books.agent"` в момент, когда агент не выполняет сборку или печать. Контейнеры стартуют вместе с Docker Desktop. Если Mac уходит в сон или пользователь выходит из системы, обработка останавливается до возобновления работы.

## Обновления и откат

Для обновления сохраните копию, затем выполните `git pull --ff-only` и `mac up -d --build --wait` в постоянном проекте. Перезапустите агент, если менялся его код. Для согласованной резервной копии остановите запись, оставив базу запущенной, и выполните `scripts/dashboard-data backup macos "$HOME/books-backup-ДАТА"`. Храните копии отдельно от Mac и Git. Сохраняйте том Caddy при обновлениях, чтобы браузер и агент продолжали доверять сертификату.

Если Mac ещё не принимал изменения и агент не подключался, восстановите работу на сервере командой `docker compose --env-file .env.server -f compose.server.yaml up -d --wait dashboard`, запустите прежний агент с прежним адресом и верните нужную настройку мониторинга. Остановите локальные контейнеры командой `mac stop`. После включения рабочей записи на Mac старая база устаревает. Для отката сначала остановите запись на Mac, снимите новую копию и восстановите её в свежие серверные тома. Сверьте незавершённую сборку и печать, затем переключите агент на серверный адрес. Старый сервер и копию храните до проверки переезда.
